# البنية وحدود المسؤوليات

## المعتمد

Notion هو المصدر الأساسي للأفكار والنصوص وحالات التحرير. خطة المحتوى ١٠٠ فكرة: ٤٠ طويلًا و٦٠ قصيرًا. يحتفظ Git بالتوثيق التقني والتنفيذ القابل للمراجعة، وبالتصدير الخام المنقول من Notion. لا توجد مزامنة نشطة أو منظومة إنتاج عاملة في مرحلة التأسيس.

| المساحة | المسؤولية والحالة |
| --- | --- |
| Notion | مصدر الأفكار والنصوص وقرارات التحرير |
| `content/notion/README.md` | فهرس ١٠٠ بطاقة |
| `content/notion/pages/<NotionID>.md` | ١٠٤ صفحات من التصدير مع روابط محلية |
| `content/notion/assets/` و`data/` | ٤ صور PNG وملفا CSV |
| `content/notion/manifest.json` و`pipeline.json` | بيان النقل والبيانات المنظمة |
| `docs/` | التوثيق التقني |
| `automation/scripts/sync_notion.py` | أداة موجودة لمرآة API محددة النطاق |
| `automation/notion-sync.config.json` | إعداد النطاق ومسار الإخراج |
| `.github/workflows/notion-sync.yml` | سير عمل موجود، يدوي وكل ساعة، مع شرط تفعيل وحد زمني ٣٠ دقيقة |
| `automation/workflows/notion-sync.yml.template` | قالب مرجعي غير تنفيذي |
| `tests/test_sync_notion.py` | ٧ اختبارات محلية |
| `content/notion/api-current/` | مسار مستقبلي يُنشأ عند تشغيل ناجح؛ JSON وأصول API منفصلة عن التصدير |

لا يوجد مجلد `rawexport/` أو تطبيق إنتاج أو هيكل monorepo. أتمتة الإنتاج وتخزين مخرجاته إضافات مستقبلية حسب الحاجة. [تفاصيل المزامنة](notion-sync.md) توضح نطاق API وحدوده؛ تجهيز الأداة لا يعني تشغيل المزامنة. سير العمل محجوب بشرط `vars.NOTION_SYNC_ENABLED == 'true'`؛ يلزم إعداد سر `NOTION_TOKEN` لتكامل للقراءة فقط وضبط المتغير `NOTION_SYNC_ENABLED` إلى `true` قبل تشغيل فعلي ناجح.

## البنية المقترحة

منسق مثل n8n يقرأ سجل محتوى محددًا، وينشئ مهمة إنتاج ذات مراحل مستقلة: نص، صوت، صور مرجعية، تحريك، تجميع، مراجعة، موافقة، ثم نشر. تُحفظ المخرجات الكبيرة في تخزين كائنات، ويحتفظ سجل الوظائف بالمعرّفات والحالات والنسخ والبصمات والتكلفة.

تُراجع ملاءمة n8n ومزودي النماذج وElevenLabs وواجهة Kling الرسمية وFFmpeg قبل اعتمادهم. تفاصيل التكامل في [التكاملات](integrations.md)، وتسلسل الجودة في [مسار الإنتاج](production-flow.md).

## عقد المهمة المقترح

كل مهمة تحمل معرف محتوى ثابتًا، ونسخة النص، والهدف التعليمي، والشخصيات، ونوع الفيديو، والميزانية، وحالة كل مرحلة. كل أصل يحمل معرّفًا وإصدارًا وبصمة ملف، ومصدره ومعرّف وظيفة المزود عند وجوده. كل موافقة ترتبط بالنسخة والبصمة ومن وافق وتوقيت الموافقة.

يُشتق مفتاح منع التكرار من المحتوى ونسخته والمرحلة ومدخلاتها. يجب أن يكون حجز المهمة وتحديثها آمنين أمام التنفيذ المتزامن. عند انقطاع اتصال وظيفة مدفوعة، استعلم عن الوظيفة الموجودة قبل إنشاء غيرها؛ لا تعِد الدفع بسبب نتيجة غير مؤكدة.

## الثبات والتكلفة

- حد إجمالي وحدود لكل مرحلة قبل بدء الإنفاق؛ توقف واضح عند بلوغها.
- إعادة محاولة محدودة مع تصنيف أخطاء قابلة للمحاولة وأخطاء تتطلب تدخلًا.
- استكمال من آخر مرحلة صحيحة، مع إعادة المراحل التابعة فقط عند تغير مدخلاتها.
- سجل نشر مستقل لكل منصة، يربط النسخة المعتمدة بمعرّف المنشور وحالته. عالج الاستجابة المفقودة بالمطابقة قبل إعادة الإرسال.
- أسرار خارج Git، وصلاحيات بالحد اللازم، وسجلات لا تعرض بيانات الاعتماد.
